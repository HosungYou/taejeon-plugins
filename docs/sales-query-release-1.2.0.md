# 태전 업무비서 1.2.0 · 매출 조회 재사용

상태: 소스 후보. 설치·발행 완료를 뜻하지 않는다. 서버 MCP 0.5.0의 새 규격과 본인 계정 활성화가 선행 조건이다.

## 변경

품목명·브랜드와 거래처명을 문맥으로 구분하고 사용자가 품목으로 정정하면 등록 품목 검색으로 이어간다. 특정 발화·두 코드에 전용 라우팅을 추가하지 않는다.

지원 규격이 확인되면 최초 조회에서 받은 queryRef를 같은 기간·거래처 범위로 보존해 품목 합계·일/주 추이·상세 페이지를 읽는다. 모든 페이지마다 전체 ERP 원장을 다시 수집하지 않는다. 미리보기 밖에 품목이 없다는 이유로 매출 0원이라고 답하지 않는다.

원천 수집/계산/표시 페이지의 완전성을 구분한다. pending이면 같은 작업의 상태/결과를 읽고, partial/failed/cancelled에서 확인된 부분 소계를 최종 매출로 표시하지 않는다. ERP가 제공하지 않는 수량·단가·세금·원천 갱신 시각을 만들어내지 않는다.

서버 수집은 접수 후 10분 이내 유한 복구이며 원장은 작업 종료 후 24시간 보존한다. 사용자가 중지를 요청하면 해당 queryRef의 cancel을 실행한다. 브라우저 종료/새로고침은 취소가 아니다. 외부 호스트의 일반 Stop 버튼·닫힌 대화에 대한 자동 최종 답변·대화 삭제 이벤트를 패키지가 연결한다고 주장하지 않는다.

두 manifest 버전/설명은 일치한다. MCP 주소·인증·공유 범위·요청 권한은 유지한다. 새 설치 지침은 실제 서버 schema에 없는 필드를 보내거나 활성화되지 않은 기능을 약속하지 않는다.

## 발행 전 확인

1. Core 서버/하네스 PR과 additive DB schema, Queue/복구 cron, 기존 예산 안의 운영 가능성을 검증한다. 기본 OFF이며 본인 계정으로만 먼저 켠다.
2. Core/Codex/ChatGPT/Claude 각각 새 인증 연결에서 MCP 0.5.0의 queryRef/action/itmno/trend 입력을 확인한다. 오래 캐시된 tools/list와 실제 서버 버전을 구분한다.
3. 전체 9월→품목 정정→두 코드 합계→추이→상세 다음 페이지를 완료한다. 최초 수집 후 원천 ERP 요청 0회, 네 환경의 금액/조건/완전성 일치, 중지/부분 복구/재열기/만료를 확인한다.
4. 서버 readback 후 이 패키지를 발행하고 실제 설치 1.2.0과 최종 업무 완료를 확인한다. 플러그인 패키지 검사는 실계정 업무 검증을 대신하지 않는다.
5. 본인 계정 네 환경 검증과 기존 운영 예산 gate 뒤 전체 허용 계정으로 확대한다.

서버 기능을 롤백하더라도 참조 없는 offset으로 전체 원장을 다시 수집하도록 안내하지 않는다. 기존 대화 요약을 최신 매출로 바꾸지 않는다.
