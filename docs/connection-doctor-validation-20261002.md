# 공통 연결 진단 구현·검증 — 2026-10-02

상태: 로컬 소스 구현. 플러그인 1.1.1은 출시 후보이며 원격 반영·운영 배포하지 않았다.

## 실제 조회 시도

2026-10-02 15:39:54 KST에 실제 Mac의 Codex 앱 내장 실행기 0.159.2,
설치된 플러그인 1.1.0(enabled=true)으로 정상 app-server 프로토콜의
`initialize → mcpServerStatus/list(serverName=taejeon-core)`를 실행했다.

결과: `authStatus=notLoggedIn`, `stage=authentication`, `toolCount=0`,
`canQuerySales=false`. MCP 초기 연결의 initialize에서 Auth required로
거절된다. 매출 도구를 실행할 수 없었고 매출 금액을 확보하지 못했다.
실패를 0건이나 0원으로 반환하지 않았다. 토큰·권한·설정 변경 없음.

서버 화면의 활성 OAuth 세션은 별도 증거다. 현재 실행기가 그 인증을
이용하지 못하는 원인이 저장 실패인지, 다른 호스트/장치의 세션인지,
연결 식별자 불일치인지는 아직 확정하지 않았다.

Core 웹에서 같은 계정으로 비교 조회를 시도했지만 Aside가 다른 작업의
OneDrive 탭으로 바뀌어 입력 전에 중단했다. 웹 매출 요청도 제출되지 않았다.

## 이전 성공과의 구분

사용자가 참조한 「태전 업무비서 MCP 화면 원인 찾기」의 기록에는
최소윤 과장님의 ChatGPT MCP 인증·도구 목록 조회 성공이 있다. 이후
「최소윤 과장 MCP 접근 오류 재현」의 운영 로그 분석에는 매출 도구
호출 기록이 있다. 별도의 직접 ERP 수집기 표본 조회 성공은 외부
Codex 플러그인으로 같은 업무를 완수한 증거가 아니다.

## 구현 범위

- Mac·Windows·Linux에서 Node 내장 모듈과 실제 Codex 실행기를 사용.
- 호스트가 제공한 실행기와 지정 실행기를 우선하여 PATH의 구형 CLI 혼동을 줄임.
- 설치·활성화·초기 인증·도구 목록·실제 매출 호출 상태를 분리.
- 인증되지 않았거나 연결 진행 중이면 매출 호출을 실행하지 않음.
- 정상 연결에서는 명시한 기존 로컬 채팅을 resume한 뒤 확인된 코드와 날짜로
  `erp_live_sales_summary`만 호출. 새 채팅·모델 턴·권한 확대 없음.
- 실패·부분 조회·정상 빈 결과·복구 조각을 분리. 원시 인증이나 명세 미출력.
- 정상 초기 연결 45초, 매출 요청 75초의 제한시간. 무한 재시도 없음.

## 검증

`node --test`: 27개 통과. `node scripts/validate-plugin.mjs` 및
`git diff --check` 통과. 실제 자식 프로세스 I/O로 JSON-RPC 응답 연결,
알림 혼재, 제한시간, 조기 종료를 검증했다. Windows 경로 우선순위도 검증했다.
CI에 ubuntu/macos/windows matrix를 추가했으나 원격 CI는 실행하지 않았다.

Windows 실계정의 인증 저장소·브라우저 콜백 및 실제 매출 호출은 미검증이다.
Codex 호스트 자체의 인증 저장 버그를 수정했다고 주장하지 않는다.
