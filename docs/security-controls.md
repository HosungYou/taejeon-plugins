# 플러그인 배포 변경 통제

현재 패키지는 실행 hook·로컬 명령·공용 인증 헤더 없이 하나의 Core HTTPS MCP 서버만 연결합니다.

## 자동 검사

```sh
node scripts/validate-plugin.mjs
node --test scripts/validate-plugin.test.mjs
```

검사: 지정된 패키지 파일·디렉터리만 허용, 심볼릭 링크 거부, MCP 서버 URL 고정, 명령·환경값·인증 헤더·추가 서버 거부, 마켓플레이스 경로와 인증 정책 일치, 두 manifest의 이름·버전·UI 일치.

GitHub Actions 검사 이름은 **Plugin package security**입니다. 읽기 전용 권한이며 외부 Action은 커밋 SHA에 고정하고 checkout 자격증명을 남기지 않습니다.

이 검사는 설명·예시 프롬프트의 의미, 이미지 속 개인정보, 승인된 서버의 런타임 보안을 자동으로 보증하지 않습니다. 문구·이미지·검사 코드 변경은 diff를 직접 검토해야 합니다. 서버의 인증·권한 검사가 별도로 필요합니다.

## main 보호 제안 — 적용 전

- PR을 통해 변경하고 필수 상태 검사에 **Plugin package security** 지정.
- 새 커밋마다 검사하고 최신 main과의 통합 상태 확인.
- force push 및 브랜치 삭제 차단, 관리자에도 검사 적용.
- 단독 관리자가 직접 승인할 수 없는 추가 리뷰어 수를 필수로 강제하지 않음.
- 정상 사용자 설치를 위해 공개 여부와 `main` 참조는 이번 변경에서 유지.

**워크플로 파일 추가와 GitHub 보호 설정 적용은 다릅니다.** 보호 설정은 서버측 readback으로 확인해야 하며 이 문서가 적용 증거는 아닙니다. 검사가 실제 GitHub에서 성공한 뒤 저장소 관리자가 구체 설정을 승인하고 적용합니다.

보안 발견 사항과 재현 코드는 공개 이슈·README에 올리지 않습니다. 비밀값이 노출되면 Git 기록 삭제만으로 해결됐다고 보지 않고 해당 자격증명의 철회를 우선합니다.
